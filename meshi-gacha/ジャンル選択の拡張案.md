# ジャンル選択の拡張案

## 目的

現在の固定ジャンル（おまかせ、居酒屋、ラーメン、カフェ）に加え、ユーザーが項目にないジャンルを選び、希望するジャンルのお店を検索できるようにする。

## 画面の変更案

### STEP 4：ジャンル選択

既存の選択肢に「それ以外から選ぶ」を追加する。

- おまかせ
- 居酒屋
- ラーメン
- カフェ
- それ以外から選ぶ

「それ以外から選ぶ」を選んだ場合は、追加のジャンル選択欄を表示する。

### 追加のジャンル選択欄

- ジャンル名で絞り込める検索ボックス
- ホットペッパーAPIから取得したジャンル候補を表示
- よく使われるジャンルを10件前後、初期候補として表示
- 候補を選択して次のSTEPへ進める
- 該当候補がない場合でも、入力したキーワードを使った検索を可能にする

初期候補の並びや検索結果は、画面幅に応じて読みやすく配置する。候補の件数はAPIの仕様・取得可能件数を確認したうえで決定する。

## 想定する操作の流れ

1. ユーザーがSTEP 4で「それ以外から選ぶ」を選択する。
2. 画面がジャンル検索欄と候補一覧を表示する。
3. ユーザーは一覧からジャンルを選ぶか、検索ボックスに語句を入力する。
4. 候補を選んだ場合はジャンルコードを、自由入力の場合は検索キーワードを検索条件に設定する。
5. STEP 5以降の既存の条件選択を経て、店舗検索を実行する。

候補を選択する方式と自由入力する方式のどちらを最終仕様とするかは、ホットペッパーAPIで利用できる検索条件を確認して決定する。自由入力語をそのまま店舗検索へ渡せない場合は、ジャンル候補の絞り込み専用にするか、候補選択を必須にする。

## バックエンド/API連携案

本番では、ブラウザーからホットペッパーAPIを直接呼び出さず、AWS上のバックエンドを経由する。APIキーはバックエンド側で管理し、フロントエンドのコードやブラウザーへ返すレスポンスに含めない。

バックエンドに必要となる処理の例：

- ジャンル候補を返すエンドポイント
- 必要に応じたジャンル名検索・絞り込み
- 店舗検索エンドポイントで、選択されたジャンルコードまたは検索キーワードを受け取る処理
- ホットペッパーAPIへのリクエスト変換、レスポンスの整形、エラー処理
- ジャンル一覧のキャッシュ（APIの利用条件・更新頻度を確認して設定）
- 入力値の検証、リクエスト数の制御、ログからのAPIキーなど機密情報の除外

既存の店舗検索バックエンドがある場合は、新しいサービスを別途立ち上げるのではなく、そのAPIにジャンル取得・検索条件対応を追加する。

## フロントエンドで扱う検索条件案

ジャンルは、固定ジャンル・APIのジャンル・自由入力を区別して保持する。

```json
{
  "genre": {
    "kind": "api",
    "id": "APIから取得したジャンルコード",
    "label": "ジャンル名",
    "keyword": null
  }
}
```

自由入力を検索に利用できる場合の例：

```json
{
  "genre": {
    "kind": "keyword",
    "id": null,
    "label": "入力したジャンル名",
    "keyword": "入力した検索語"
  }
}
```

実際のフィールド名やコードの形式は、バックエンドAPI仕様とホットペッパーAPIの仕様に合わせて確定する。

## 表示状態・エラー時の扱い

- 読み込み中は候補欄に読み込み状態を表示する。
- 候補が0件の場合は、該当候補がないことを明示する。
- API取得に失敗した場合はエラーを表示し、再試行できるようにする。
- API障害時に固定ジャンルを利用できるかは、検索処理がそのジャンルに対応できることを確認して決める。利用できない条件を成功したように見せない。
- 「戻る」でSTEP 4へ戻ったとき、選択済みジャンルや入力語を保持する。
- 検索結果や条件表示に、選択したジャンル名または検索語を反映する。

## 実装前に確認すること

- ホットペッパーAPIで取得可能なジャンル一覧・識別子・検索条件
- APIの利用規約、利用制限、キャッシュ可否、表示要件
- AWSバックエンドの実行環境と既存エンドポイント
- 自由入力キーワードを店舗検索APIへ渡せるか
- 候補一覧を全件取得してクライアント側で絞るか、検索のたびにバックエンドへ問い合わせるか
- 初期表示する「10件前後」の選定方法（利用頻度、APIの並び順、運用側設定など）

## 完了条件案

- 既存の固定ジャンルをこれまでどおり選択できる。
- 「それ以外から選ぶ」から候補の表示・検索・選択ができる。
- ジャンルコードまたは検索語が、店舗検索まで正しく引き継がれる。
- 戻る操作で入力内容が保持される。
- 読み込み中、候補なし、APIエラーが区別して表示される。
- APIキーがフロントエンドへ露出しない。
- PC・モバイルの両方で選択肢と検索欄が操作できる。
